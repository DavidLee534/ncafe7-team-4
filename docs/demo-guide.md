# 시연 가이드

지금까지 구현한 시스템(1.0~16.0)을 시연할 때 DB를 준비하는 방법과 시스템별 시연 순서입니다.
15.0 메인 페이지는 아직 정적 화면이라 시연에서 뺍니다.

## 1. DB 준비

시연은 **로컬 PostgreSQL(`ncafe-postgres`)** 로 합니다. H2는 자동 테스트(`./gradlew test`)에만 씁니다.

> **공용 클라우드 DB에는 시작 데이터를 넣지 않습니다.** 아래 명령은 모두 각자 컴퓨터의 DB에만 씁니다.

컨테이너와 `backend/secret.properties`가 없으면 [local-db.md](local-db.md) 1~2번을 먼저 합니다.
시연 데이터는 시연 중에 바뀌므로(주문, 발견, 자랑글) **리허설 뒤와 발표 직전에 매번** 아래 1~4를 합니다.

**1) 백엔드가 켜져 있으면 끄고, DB 비우기** — 로컬 DB의 데이터가 모두 지워집니다

```bash
docker exec ncafe-postgres psql -U ncafe -d ncafedb -c 'drop schema public cascade; create schema public;'
```

**2) 백엔드 켜기** — 테이블이 새로 만들어집니다

```bash
cd backend
./gradlew bootRun
```

`Started BackendApplication`이 보이면 켜 둔 채로 다음 단계로 갑니다.

**3) 시작 데이터 넣기** — 다른 터미널의 `backend` 폴더에서

```bash
sed -E "s/listagg\(cast\(id as varchar\), ','\) within group \(order by id\)/string_agg(cast(id as varchar), ',' order by id)/" \
  src/main/resources/data.sql \
  | docker exec -i ncafe-postgres psql -v ON_ERROR_STOP=1 -U ncafe -d ncafedb
```

- `data.sql`의 비밀 레시피 조합은 H2 함수(`listagg`)로 되어 있어서, 그 부분만 PostgreSQL 함수(`string_agg`)로 바꿔서 넣습니다. 저장소의 파일은 바뀌지 않습니다
- PowerShell에서는 Git Bash나 WSL에서 실행합니다
- 오류가 나면 1)부터 다시 합니다 (두 번 넣으면 이름 중복 오류)

**4) 확인**

```bash
docker exec ncafe-postgres psql -U ncafe -d ncafedb -c "select count(*) from secret_recipes where ingredient_combo is not null"
```

`8`이 나오면 됩니다. 백엔드는 그대로 켜 둡니다.

### 프론트 켜기

```bash
cd frontend
npm run dev
```

브라우저에서 **`http://localhost:3000`** 으로 엽니다. (`192.168.x.x:3000`으로 열면 로그인 쿠키가 따로 놀 수 있습니다)

## 3. 시스템별 시연

추천 순서: **손님(16 → 8 → 9 → 10 → 11 → 12 → 14 → 13) → 관리자(7 → 1 → 2 → 3 → 4 → 5 → 6)**
손님 흐름에서 만든 주문과 포션을 관리자 화면에서 다시 보여 주면 이어집니다.

| 4 | 모카로 그 조합을 연금술로 만들기 | 방금 추가한 비밀 레시피를 발견 |
| 5 | 발견된 비밀 레시피 삭제 | 거절 ("숨김으로 바꾸세요") |

### 5.0 주문 관리 (`/admin/orders`)

| 순서 | 할 일 | 보여 줄 것 |
|---|---|---|
| 1 | 목록, 상태 필터 | 시작 주문 6건 + 시연 중 주문 |
| 2 | 12.0에서 모카가 한 주문(`paid`) → 제조 중 → 준비 완료 → 완료 | 한 단계씩만 넘어감 |
| 3 | 모카 창에서 `/my/orders` 새로고침 | 바뀐 상태가 보임, 제조가 시작된 주문은 취소 불가 |
| 4 | 다른 `paid` 주문 취소 | 취소된 주문은 다시 바꿀 수 없음 |

### 6.0 회원 관리 (`/admin/members`)

| 순서 | 할 일 | 보여 줄 것 |
|---|---|---|
| 1 | 목록, 검색, 상세 | 회원별 주문 수, 포션 수 |
| 2 | 치즈 정지 | 치즈 창에서 다시 로그인하면 거부. 정지를 풀면 다시 로그인됨 |
| 3 | 관리자 계정 정지·삭제 | 거절 |
| 4 | 주문이 있는 회원(모카) 삭제 | 거절 ("정지로 바꾸세요"). 16.0에서 만든 새 계정은 삭제됨 |
